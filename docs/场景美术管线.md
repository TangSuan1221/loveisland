# 荒岛心跳 · 场景资产制作与验收

适用范围为营地、海岸、岩体、植被、异星地标、远景和后续同类资产。项目使用 Three.js 0.180.0。下列比例、线宽和性能阈值是预研建议值。正式量产前，用独立评审通过的游戏截图锁定第一版基准，记录截图、参数与代码版本。

## 三张示意图各管什么

| 标准镜头 | 主参考 | 制作时观察 | 审图方法 |
|---|---|---|---|
| 营地近景 | 第一张 | 沙地留白托出圆筒舱，窗门比舱壁暗，橙布下垂，杆脚有接触影。巨树和水湾构成不对称画框 | 各裁出舱门、板缝、棚布、岸线四个局部，在相同屏幕尺寸下并排 |
| 海岛远景 | 第二张 | 巨菌、岩台、肋骨与小营地形成明确大小级差。远景蓝灰、低对比，岩台顶沿和有机地标仍可辨认 | 缩到 256 像素宽，读出主地标、营地位置和海平面。比较前中远三层明暗 |
| 玩法全景 | 第三张 | 菌群在左后、骨弧在右后，舱和橙棚靠中，码头伸向右下。建筑周围留出工作面，浅水包住沙滩 | 在两图标注五个地标的重心与覆盖范围，检查遮挡和玩家落脚面。格线可按建造模式单独开关 |

第二张的前景人物和标题不计入环境资产评分。不同镜头使用各自的原图比例；把方图拉宽会错误改变骨弧与菌盖的形状。参考作品名称用于沟通气质，具体轮廓和取色以用户示意图对应区域为准。

## 从图到资产

1. **建立资产卡。** 记录资产 ID、用途、主参考及裁切坐标（以原图左上为原点的 0–1 坐标）、主要游戏镜头、屏幕占宽、锚点、通行边界、源文件、作者、来源与授权。每件资产选一张同类物作尺度参照，例如舱门对箱子、舱顶对菌盖。
2. **先看黑形。** 出正面、四分之三面和实际游戏镜头三张黑色剪影。将游戏镜头缩至目标屏幕宽度的四分之一。菌盖与骨尖应保持分离，遮阳棚顶与舱顶能各自勾出轮廓。此轮只修改比例、姿态和空间间隔。
3. **画明暗分区。** 先铺面积最大的固有色，给每种材料画背光面和局部暗缝。用三块代表色检查亮面、转折面、背光面的面积。凹洞、折痕、苔斑随结构走向，不均匀铺满表面。通过后才进入小划痕、铆钉和点状植被阶段。
4. **建模与画线。** 影响多个角度轮廓的特征进入网格。窄板缝、锈迹、木纹和树皮划痕进入纹理或带遮挡测试的贴花。优先让几何体自身的遮挡产生深色交界，视距变远时合并微小线条。以 1080p 游戏截图为起点，主体外缘约 1–2 px，内部线多为断开的 1 px 细线；按最终实拍重新定值。
5. **组装并定标。** 统一 Y 向上、1 单位对应 1 米；摆件原点落在底面中央，门轴等活动部件单设局部枢轴。资产与地表接缝、建筑入口、菜地操作侧和码头落脚面在游戏镜头中复检。几何、碰撞和交互区域分别命名；着色、随机变体、局部摆动由同一资产 ID 重建。
6. **归档。** 程序化资产提交工厂函数、种子和参数；手工资产提交可编辑源文件、GLB、贴图、许可说明。两者均提交同机位全景和细节截图。外部资产另记原链接、版本、作者、改动和署名位置。授权与用途匹配后进入公用资产目录。

## 分资产施工标准

| 类别 | 首先制作 | 游戏镜头下必须看见 | 最常见返修 |
|---|---|---|---|
| 巨菌、骨弧 | 菌柄从根部分叉，菌盖偏心起伏、下沿有厚度；骨根粗、骨尖细，各根曲率与高度递变 | 盖顶莓紫、盖底蓝紫；相邻菌之间能透光，骨尖从树丛上方连续露出 | 均匀圆盘改轮廓；黑点改带内壁和阴影的凹洞；等距复制的骨弧改姿态 |
| 棕榈、灌木、珊瑚 | 棕榈以中轴弯折的分裂叶组成，灌木按大小相嵌的体块成簇。珊瑚分叉沿一根主生长轴 | 近处见叶裂与枝节，中距离只剩叶群；局部珊瑚色引导视线 | 去除均匀散点；变体同步改变冠幅、分叉和侧倾 |
| 岩壁、草地 | 岩体建立破裂面和偏斜的台阶，让苔随顶部与裂口生长；草地分整块底色与局部草簇 | 顶部暖绿、立面冷紫灰，裂线可数，路径旁留裸土 | 替换遍地三角面硬边，合并高频斑点 |
| 沙滩、海水 | 海床坡度确定浅滩边界，岸线沿地形绕过岩块；水面布置大小两级碎波与断续白线 | 湿沙、薄荷浅水、青蓝深水方向清楚。岩脚有局部环流和断泡 | 泡沫线打断、变宽；缩短重复纹理，降低远处线条对比；缓动一周期检查泳动 |
| 舱体、棚布 | 先以人尺度搭舱门，再做偏拱顶、压条、窗框、板块。橙棚角点拉紧，布心下垂 | 亮舱壁托出深门窗；锈迹靠螺栓与接缝；棚边和杆在剪影中分开 | 镜面改哑光，板缝随曲率，棚角高度错开；补门槛、支撑和接地 |
| 农具、箱、菜地、码头 | 箱体大小不一、木板端头可读；作物按地块分行；栈桥由踏板、桩、系缆组成 | 远处可识别用途，近看有组装方式和使用痕迹 | 将次要道具归组，移走遮门的箱子，缩减跨板重复木纹 |
| 远景岛峰 | 单独设远景层，建立主峰、不规则次峰、海平面剪影与稀疏云带 | 与主岛留空气间隙；雾色更靠近天空，轮廓细节逐层减少 | 拉开层间明度，减少深线与纹理频率，复检景观镜头 |

## 配色与 Three.js 接入

初版比色卡可从沙杏色 `#F1CE91`、草橄榄 `#91A553`、浅滩绿 `#70CEBD`、海青 `#388BA8`、菌顶莓紫 `#AD5086`、菌底靛紫 `#444364`、棚橙 `#D88743`、舱灰白 `#D9D2C9`、墨色 `#33323F` 起步。此组是目测建议。锁色时在用户原图的亮面和背光面各取三个干净的 5×5 像素区域，记录 RGB 中位数及裁切位置；测试画面也取相同材质区域，避免把白沫、线稿和边缘混在一起平均。对光照前的固有色和显示截图色分别建表。

- **色彩链。** 基色贴图与含颜色的画布标注 `SRGBColorSpace`，数据贴图保留 `NoColorSpace`。线性空间计算光照，最后只做一次输出转换。锁定曝光、色调映射、方向光、填充光和屏幕输出色域；接入后期时重新检查白舱、暖沙、菌盖三块基准。[Three.js 色彩管理](https://threejs.org/manual/pages/color-management.html)
- **块面。** 有体积的资产可用 `MeshToonMaterial.gradientMap`，灰阶纹理的放大、缩小均用 `NearestFilter`。同材质共用一组色阶，手绘纹理提供局部色差。水面和远景若使用自定义 shader，先用纯色色卡做与常规材质的并排校准。[Three.js MeshToonMaterial](https://threejs.org/docs/pages/MeshToonMaterial.html)
- **线稿。** 资产轮廓可用平滑法线扩张的背面壳，硬表面的精选结构线随模型绘制。模组导入后留意分离顶点导致的断线。玩法选中态可以单独用 `OutlinePass.selectedObjects`，截取验收图前关闭选中效果。[Three.js OutlinePass](https://threejs.org/docs/pages/OutlinePass.html)
- **交付接口。** GLB 由 `GLTFLoader` 导入；保留材质槽名称，按类别映射项目着色器，校验原有透明度、双面叶片、UV 与顶点色。相同植物、木桩和岩块共享几何与材质。性能记录需给出场景种子、浏览器、GPU、分辨率、draw calls、三角数及帧耗时分位数。建议预算由目标设备实测决定。[Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)

## 视觉回归与独立盲测

1. 固定构图、画布尺寸、设备像素比、种子、环境光、动画时间，关闭 UI 和选中线。基准至少包括玩法全景、营地近景、地标远景；另录正常游玩速度下的短镜头，观察轮廓跳动、贴花闪烁、投影漏光与植被重复。
2. 资产作者先逐项把轮廓、面积、遮挡、明暗、细节尺度与对应原图并排核对。返修单必须指向具体证据，例如“菌盖投影宽与柄宽之比小于参考，同屏看成棕榈”，并写下准备调整的参数。修后在原种子、原机位复拍。
3. 独立评审只收到同尺寸的 A/B 像素图与目标问题，不参与编辑，不读候选名、实现、种子或版本。制作者随机分配左右，密钥留到提交判断后揭晓。保留实际图片、映射、日期、评审意见。若评审此前见过原图，记录为“未知左右身份、熟悉原图”，后续可请未接触原图者复核。文件名、标题、角色、UI 或水印足以暴露身份时，双方使用相同规则裁切。
4. 分两轮提问。参考图对候选图时，问“哪张更像手绘科幻岛屿、哪张更易读？请分别选 A、B 或平局，并指向两个局部”。新旧候选对比时，在两图外另放同一张参考，问“哪个更接近目标？” 两轮均独立记票。插画原稿与实时截图具有不同媒介特征，胜负只代表该评审在该机位的判断。
5. 每项按 0–2 记分：0 为辨认困难，1 为读得出但能指出明显偏差，2 为在主镜头与对应局部均接近参考。六项分别为构图、地标剪影、色块明暗、描线、生态与营地细节、玩法可读性。建议候选达 10/12、无零分且地标剪影与玩法可读性均为 2 时提出锁版；独立评审仍指出显著偏差时，返回相应资产步骤。记录原始分数与偏好，不以分数代写“已通过”。
6. 归档格式为“轮次 / 随机左右 / 显示尺寸 / 镜头 ID / 评审身份暴露情况 / 六项分数 / 偏好 / 画面位置及理由 / 返修资产与参数 / 复拍与复评结果”。缺任一对照原图或实际截图时，将该镜头标为待验。锁版后每种新材质先过代表资产，再扩到整个资产族。

## 在项目内复拍

双击 `art/study/island.html` 可离线查看四个机位，拖动旋转，滚轮缩放。修改资产后，在项目根目录运行 `node scripts/build-art-study.mjs` 重建这个单文件。开发时运行 `npm run dev`，在控制台打印的本地地址后加 `/?art-study`。截图加 `&clean&shot=island`，也可把镜头名换为 `camp`、`flora` 或 `vista`；此模式隐藏控件并固定动画时间。

当前预研使用程序化网格、顶点色、结构墨线和地表绘图。地形与岸线在 `src/artStudy/terrain.js`，植被在 `flora.js`，营地在 `camp.js`，天空在 `horizon.js`。灯光、正交相机和固定镜头共用 `studio.js`。前文的 GLB 导入和 Toon 渐变色阶适用于后续手工资产接入。量产前应分别检查直接绘色的预研件与受光的导入件在同一盏灯下能否匹配。

本机盲评工具位于 `art/study/compare.html`。制板人选两张原图，工具按随机位排列并隐藏来源；评审选 A、B 或平票并写下画面证据，提交后才显示左右文件名。直接对照示意图时使用原附件；测返修效果时使用相邻版本的实拍。

## 正式游戏复拍与网格校准

通过项目根目录的 `Play.cmd` 启动，标题的「查看初见岛」用于看新岛全貌。进入新局，签下嘉宾，取布置阶段的全岛、营地及建造中三张图。录制时再检查角色脚底、门口与节目设施的相对位置。记录存档里的 `camp.mapVersion`，旧营地会按原版岸线与建筑尺寸还原。

新版初见岛为 64 × 64 格，每格 0.75 世界单位。营地舱占 6 × 5 格，橙棚 5 × 4 格，农田 4 × 3 格，码头 2 × 7 格。侧转后交换长宽。建筑可见模型、射线拾取、放置预览、设施重叠和互动入口都从当前版本的建筑定义读取；复核时需要同时观察外观、占格和门口通行。草木、海岸和道路的绘色允许跨过格缝，地块判定始终使用原网格。

正式游戏的图形后端优先使用 WebGPU，浏览器缺少可用适配器时使用 Three.js 的 WebGL2 节点材质后端。建造相机支持旋转和缩放；做同一轮 A/B 时须锁定方位、缩放和视窗尺寸，并同时隐藏或保留双方的游戏界面。
