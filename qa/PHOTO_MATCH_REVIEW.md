# 照片自动匹配独立实机验收

2026-11-12，用户提供的 660×440 单人照片。使用隔离 Microsoft Edge、真实本机 MediaPipe 与 BiSeNet/ONNX 模型，实际 WebGPU 编辑器。未调用云端服务，未点选任何候选，未手调参数或更换预设。

## 证据与复现

- `node qa/photo-match-evidence.mjs <照片>`：等待 worker 最终 result，不能把中间 geometry 消息当成结束。取得 478 关键点与完整 512×512 分割。
- `node qa/photo-match-auto.mjs <照片> before|after`：上传→等待→直接应用→保存→检查实际角色数据与 WebGPU 后端。照片候选选择次数始终为零。
- `qa/photo-match-comparison.html`：读取 before/after 实际自动结果，使用同一当前模型与同一镜头渲染；输入照片经本地 file input 裁剪显示。截图 `qa/photo-match-comparison.png`。
- 关键点、mask、RGBA 只保存在 git 忽略的 `photo-fit-evidence.json`，自动参数记录为忽略的 `photo-match-*-result.json`；用户照片不进入公开游戏资产。

## 发现与迭代

1. 旧路径实际自动选择旧整发 `quiff`，前后层仍 auto；三个旧候选分数非常接近。round 脸被横向扩宽，粗 square 框和过长近似平嘴进一步削弱照片特征。基线图 `photo-match-before-automatic.png`。
2. 第一轮接入新发层后出现 `slick_3 + doublebun_5`。实际画面是照片中没有的两个大丸子，明确判为失败，不能因为无异常或参数有效而通过。
3. 反馈后修正背发评分、额外轮廓惩罚、共同头顶尺度与统一镜像方向；对看不见的绑发结构只给候选，不自动断言。之后自动选择 `slick_6 + sweptback_1`，实际画面不再出现旧高顶团或双髻。
4. 薄矩镜框的 size=1.3 原本同时拉开左右镜片中心，瞳孔不居中。Root 改为只改变镜片尺寸，镜片中心保留与眼位的关系；复拍确认对齐改善。
5. 脸部等比坐标替代分轴归一化，新梨形轮廓的宽高关系比旧扁圆更贴近照片。可见露齿证据使笑容选择 grin，改变原来近似平嘴。眉色低可靠时保留原值，避免把皮肤色当成眉色。

6. 第二张官方QA短发照片交叉测试又暴露 `curl_5 + auto` 保留旧 bob 的问题。已补基础发冠候选、贴头薄发体积约束以及可靠短发证据的后发替换，最后复拍两张照片均无多余大卷冠或旧长后发。该控制照片无镜框，维持 none；大笑与目标照片的较小露齿开口有不同参数。

## 最终实机观察

最终自动结果包含 `pear`、`hairFront=none`（保留基础发冠、无垂落刘海）、`sweptback_1`、`glasses_rectangle`、`grin`。镜片大小 1.213、粗细 0.602、高低 0.0051，来自当前脸部变形后的真实比例；眉宽改为独立缩放，不再同时放大眉峰高度。真实运行零页面异常、零外部 HTTP 请求、零人工候选选择。对照图显示露额短灰发、较接近原图的头部纵横比例、细镜框、露齿笑得到改善。

结论仅限本次自动匹配流程及该输入的观察，不能当作一般化身份相似度成绩。头发分缝与发际线精细曲率、年龄纹理、照片光照下的颜色和任意单张照片的背面结构仍未完整恢复。检测/拟合残差不等于人物相似度，旧新坐标系的残差也不能直接比较百分比。该功能仍应提供候选、保留与继续手调。
