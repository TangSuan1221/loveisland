# 角色交互与动画循环静态代码审查

审查范围：`src/main.js`、`src/characters.js`；另读取 `src/style.css` 验证隐藏元素与键盘焦点样式。审查日期：2026-11-12。源码保持冻结，仅新增本报告。

本报告依据代码路径推导，未操作浏览器、未执行交互流程、未替代30分钟生产运行测试。以下复现步骤均为建议验证步骤，不表示已经实际复现。

## 严重性结论

未发现足以确定为P0或P1的阻断缺陷。发现数个P2交互一致性问题与有限的性能改进项，不能把它们升级描述成崩溃、持续内存泄漏或运行测试失败。

## 核心检查结果

### 每帧 focusActor 不会重置动画

`characters.js:306` 的 `focusActor` 只写入 `focusedId` 与复用的 `focusCamera` 向量，不重置 `elapsed`、`visualElapsed`、`_travel`、眨眼相位或动作状态。因此 `main.js:166` 每帧调用不会导致动画从头播放，也没有在此路径反复创建纹理、几何或相机。

角色朝向在 `cast.update` 内更新，而镜头补间和最新 `focusActor` 在其后执行，产生约一帧的目标滞后；平滑旋转下属于可接受的实现取舍，不是阻断。若以后要求更紧密的跟随，可先更新镜头与focus，再更新角色。

### 暂停的实际合同是冻结全部场景动画

`main.js:163` 暂停时完全不调用 `cast.update` 或 `island.update`，所以角色呼吸、眨眼、步行均冻结；相机控制和UI仍工作。该行为与当前按钮“暂停场景动画”和“时间停在这一刻”文案一致。

`characters.js` 单独使用 `setPaused(true)` 并继续 `update` 则只停止行走、保留呼吸及朝向更新。两层暂停合同不同，当前主入口以main层为准。不能声称当前集成版“暂停仍保留呼吸”。

### 资源分配没有发现随正常选人次数增长的GPU对象

角色几何、材质、织物DataTexture在初始化构造；每帧主要修改变换。人物卡使用初始化时生成的6张头像data URL，不在每次选人时创建新WebGLRenderer或重新渲染头像。`portraitRenderer.dispose()` 已执行。

头像clone共享原角色几何和材质，不能为了释放头像而逐个dispose共享几何/材质，否则会影响主场景。头像渲染器和主渲染器的GPU资源生命周期需分别管理。

## 性能与生命周期风险

1. `main.js:61` 始终启用 `preserveDrawingBuffer:true`。这是固定渲染成本而非泄漏；在截图前已有同步 `renderer.render` 的前提下，可另行验证关闭该选项并立即读取像素是否满足目标浏览器，再作优化。冻结期不建议未经验证直接修改。
2. `main.js:98–100` 初始化额外创建一次头像WebGL上下文，随后dispose。没有循环创建，故不是持续泄漏；可在头像导出结束后按需要 `forceContextLoss()`，同时避免销毁共享资产。新增清理逻辑应验证不影响已生成data URL。
3. `main.js:161–170` 暂停仍持续渲染，阴影也持续更新。为了允许自由相机这并非逻辑错误，但节能可以采用脏标记按需渲染；必须包括OrbitControls阻尼、补间、UI截图和光照变更，不能简单停掉RAF。
4. 每帧4个地标 `.clone()` 产生少量短生命周期Vector3，角色眨眼的forEach回调也有小额分配。数量固定，没有无界保留；只有实测GC成为瓶颈时才值得复用向量或改循环，不应推断30分钟后必然变慢。
5. 当前没有统一dispose/unmount函数，RAF、窗口监听、QA interval、AudioContext和场景GPU资源依赖整页卸载释放。单页一次启动不会因此持续累积；若将来嵌入可反复挂载的SPA，需要取消RAF/interval、移除监听、断开音频，并按共享资产所有权dispose。
6. `runtimeErrors`数组没有上限，若未来发生每帧错误会持续增长；正常无错路径不会增长。可用固定容量环形缓冲并累计总次数，防止诊断本身放大异常。
