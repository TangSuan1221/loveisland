# NPC 行为研究与实现规格

研究日期：2026-11-12。目标游戏为 Nintendo Switch 的《Tomodachi Life 朋友收集 梦想生活》（Living the Dream，2026），用户口语中的“朋友聚会美好生活”按此理解；不是 Nintendo 3DS 的《Tomodachi Life》（2013/2014）。第二参照为《集合啦！动物森友会》（Animal Crossing: New Horizons）。

本报告是公开资料研究与工程设计，不是任天堂源码分析，也没有进行原版实机行为统计。下文明确区分**官方证实的行为**、**未公开的内部机制**、**本项目选择的实现方式**。不能凭相似的几个动画宣称完成“1:1 AI 还原”。

## 1. 证据登记

### T1：自主性与关系的双向差异

开发者明确将居民自主决定结果视为核心：玩家把两人放到一起，之后不必交谈；关系图中双方评价可能不同；关系不佳者也可能同桌聊天。扩大自由活动空间是新作与旧作的重要区别。[Nintendo：Ask the Developer，第1章，2026-04-14](https://www.nintendo.com/us/whatsnew/ask-the-developer-vol-21-tomodachi-life-living-the-dream-part-1/)

**不能推出的结论：**没有公开每次相遇概率、关系分值范围、兼容矩阵、寻路算法或行为树结构。“双方评价不同”不等于已经证明原版采用两个浮点好感值。

### T2：可复用信息与物品组合

玩家教过的话会在之后的居民交流中重新出现；居民自行使用礼物。开发团队曾处理反复踱步和多人同时争用物品，为组合行为增加规则。访谈也确认恋爱与友谊均是游玩方向。[Nintendo：Ask the Developer，第2章，2026-04-14](https://www.nintendo.com/us/whatsnew/ask-the-developer-vol-21-tomodachi-life-living-the-dream-part-2/)

**不能推出的结论：**没有公开记忆容量、遗忘算法、语义推理模型或资源锁实现。这里的“说过的话再出现”不能当作使用生成式大模型的证据。

### T3：性格与小习惯是两个层次

16种性格保留特征台词和动作；另设可赋予的小习惯，覆盖走路、进食和睡眠等表现，避免用性格类型包办所有个体差异。剧情小场景来自开发团队持续制作的内容。[Nintendo：Ask the Developer，第3章，2026-04-14](https://www.nintendo.com/us/whatsnew/ask-the-developer-vol-21-tomodachi-life-living-the-dream-part-3/)

**不能推出的结论：**不能据此宣称16类的完整映射公式、相性表和每种事件权重已经查明。不能把任意16组随机参数命名为原版等价性格。

### T4：相识、共同兴趣与居住环境

官方 Direct 摘要说明：相识后可自主往来，交流可能围绕食物或共同喜好；最多8名居民可同住；时间与现实同步；玩家可调整性格、给予习惯和口头禅。[Nintendo：2026年1月 Direct 官方摘要](https://www.nintendo.com/au/news-and-articles/tomodachi-life-living-the-dream-direct-spotlights-quirky-fun-with-player-made-mii-characters/)

**边界：**同住支持8人不意味着“8人对话”或每帧对全部室友进行关系结算；实时流逝不证明离线期间运行逐秒完整模拟。

### T5：关系事件与个体偏好

官方产品页确认朋友、争吵、告白、三角关系、恋人及婚姻；创建时可设置性别和恋爱偏好。食物、服装、礼物与建议可用于照顾居民，并探索喜恶。居民也会提出岛屿布置意见。[Nintendo：Living the Dream 产品页](https://www.nintendo.com/au/games/nintendo-switch/tomodachi-life-living-the-dream/)

**边界：**产品页列出事件类型，未公布触发阈值、拒绝概率、婚姻状态机或完整事件脚本。我们使用原创台词和事件实现这些功能类别，不复制原版全部文本。

### A1：动森的玩家—居民交流

官方指南列出每日聊天、信件礼物、生日、捕虫与转交物品等请求、失物归还。居民可能以思考气泡或跑向玩家表达需求；反复接触可让特定角色逐渐敞开心扉。[Play Nintendo：How To Be a Good Neighbor](https://play.nintendo.com/news-tips/tips-tricks/animal-crossing-new-horizons-neighbors-tips/)

**边界：**这些证明关系存在持续性，不公开统一友好度公式，也不能把服务NPC的专属流程当作所有普通居民共有算法。

### A2：动森的生活节律

官方页面确认时间与季节对应现实，居民日常与限时活动形成持续世界。[Nintendo：Explore your island](https://animalcrossing.nintendo.com/new-horizons/explore/)；[Nintendo UK：A living, breathing world](https://www.nintendo.com/en-gb/Games/Nintendo-Switch-games/Animal-Crossing-New-Horizons-1438623.html)

**边界：**没有公开离线结算代码、每种性格起床时刻和行为选择概率。本轮不把社区常见的8性格、6爱好或友好度数表列为已核实的官方技术事实；需要独立原始数据或可复现实机证据才能升级证据等级。

## 2. 两款游戏应如何分别借鉴

以下是本项目从上述材料作出的设计判断，而非开发者公布的内部架构。

| 维度 | 朋友收集应优先复现的体验 | 动森适合补充的体验 |
|---|---|---|
| 主要观察对象 | 居民彼此间的关系和意外结果 | 玩家与居民长期相处、日常生活 |
| 玩家介入 | 创造相遇机会，送礼、教词、提出建议 | 聊天、回应请求、送礼、参与日历事件 |
| 持续性 | 上次互动影响下次态度 | 日常问候与长期共同生活的积累 |
| 变化来源 | 人物组合、相识关系、偏好、习惯、环境 | 时间、季节、生活活动和居民需求 |
| 不应误读 | 不是每个按钮都保证一对人成为朋友 | 不是每一分钟都必须产生强冲突 |

用户要的“行为丰富”应同时包含：NPC不等玩家点击也会做事、不同人做不同选择、接近之后可能拒绝、互动有结果、结果下次还有效。仅随机换动作不能满足这五点。

## 3. 本项目推荐的工程拆分

以下全部是**原创工程方案**；数值可调，不声称来自任天堂。

### 3.1 独立于 Three.js 的模拟层

模拟层只持有序列化数据与种子随机数。输入为时间增量、玩家意图、场景可交互点；输出为状态快照和事件。渲染层不得通过动画结束帧直接修改关系，以免帧率改变剧情。暂停应停止模拟时钟；相机仍可操作。

每个居民至少持有：稳定ID、性格维度、偏好标签、小习惯、当前需求、情绪、位置、活动阶段、目标ID、有限记忆、已知人物、可用词汇和冷却计时。

### 3.2 日常决策层

候选动作包括散步、休息、进食、观景、阅读、锻炼、整理花草、独处和寻找熟人。按需求、偏好、地点可达性、最近重复程度、活动时段评分后做带种子的选择。

每项活动必须有持续时间与退出原因。不要逐帧重选导致来回折返；被占用的目标降低效用或加入排队，无法抵达时释放资源并重新规划。动作评分公式是我们的实现，不是原版公式。

### 3.3 双方协商与互动会话

互动不是A播放说话、B继续走路。完整会话分为 `寻找 → 邀请 → 接受/婉拒 → 前往站位 → 轮流表达 → 共同反应 → 结算 → 分开`。双方同一时间最多属于一个会话，超时或取消必须释放两方锁和场地槽位。

初次相识、聊兴趣、分享食物、共同活动、意见不合、安慰、道歉可先做为原创事件类别。事件由条件选择，不为了展示所有类型而不顾上下文轮播。拒绝是一种正常结果，不等于寻路失败。

### 3.4 有向关系与记忆

用 `A→B` 和 `B→A` 分别存亲近、信任、最近情绪与相识状态，可表达同一事件中的不同感受。分类标签由状态派生，不允许UI凭空覆盖数据。

记忆包含事件ID、参与者、时间、主题、主观评价。重复事件ID只结算一次；最近事件降低重复权重。对话可引用“上次一起看海”这样的真实记录，不能生成没有发生过的往事。保存/载入后应保留关系、偏好、词汇与记忆。

### 3.5 性格、兴趣、小习惯分离

性格影响行为倾向和回应方式，兴趣影响活动与话题，小习惯影响步态、招呼及动作节奏。角色的能力与意愿必须分开：内向者仍能主动邀请，性格差异也不应造成某角色永远没有事件。

第一轮可以使用6位现有角色的原创配置；这不是原版16类完整覆盖。后续若做16类编辑器，需要逐类观察证据和差异验收，不能只有16个标签。

### 3.6 地点与物品可供使用的行为

设施给出可用动作、容量、站位、入口和使用时间。井、餐桌、长椅、篝火各有不同活动。美术Mesh本身不承担资源管理；在地形变动后重新验证可达性。

对扩大的海岛尤其要避免“大家绕出生点转圈”。活动点应跨生活区分布；路径必须走桥、避水和建筑，不能只在XZ平面向目标插值。互斥测试应覆盖多人同时选择唯一座位和会话取消。

### 3.7 原创对话与表达层

事件数据包含说话轮次、说话者、主题、情绪、动作和文本变体。台词检索依据当前事实、关系与角色语气；小习惯与口头禅叠加在表现层。每条对话保留来源事件，避免UI气泡与模拟状态分离。

不需要接外部大模型才能做出自主性。首轮使用有条件的原创脚本与有限词汇记忆，更容易验证因果、节奏、重复率和存档一致性。若之后增加模型，只负责候选文本，关系结果仍由模拟规则决定。

### 3.8 镜头作为观察层

观察相机读取事件，不驱动事件。默认保留自由镜头；选择“跟看互动”后按接近全景、双人中景、说话者近景、结束回景组织。镜头必须同时考虑两人的站位、遮挡、屏幕UI、安全边界和用户手动打断。

此项是本项目运镜设计，当前研究不能证明原版采用同一切镜算法。不可把电影式频繁切镜等同于原作完整还原。

## 4. 1:1 行为等价的验收表

| 项目 | 本轮可建立的验收 | 尚缺证据或内容 |
|---|---|---|
| 自主生活 | 无输入运行时，各角色完成多种有目的活动 | 原作活动分布、昼夜占比与时长统计 |
| 相遇自主性 | 引荐允许接受、拒绝、延后，不直接写朋友关系 | 原作各条件下概率与冷却 |
| 双向关系 | 同一互动后两人评价可不同，存档保留 | 原作数值与状态转移表 |
| 性格与习惯 | 更改性格影响选择，习惯影响表现 | 原版16类与全部习惯逐项覆盖 |
| 偏好 | 相同礼物对不同角色反应不同 | 原作物品库和喜恶分布 |
| 社交内容 | 交谈、共同活动、冲突、安慰/修复有前因后果 | 告白、三角关系、婚姻、家庭及大量特殊事件 |
| 同住 | 居住关系可影响遇见机会 | 8人共居完整室内行为与资源竞争 |
| 学词与记忆 | 教授内容之后被NPC引用；事件不能凭空产生 | 原作词汇槽类型、文本模板全集 |
| 环境调度 | 资源不被重复占用，取消无死锁 | 任意用户岛屿布局下全量组合测试 |
| 时间 | 区分模拟时间、现实时间与暂停 | 原版离线结算和系统改时行为 |
| 动态观察 | 自动镜头能看清互动且可退出 | 原作同场景连续视频逐镜对照 |

“原版内部AI完全1:1”目前不能验收。合理的阶段名称是“对齐已证实行为的原创NPC模拟”；未实现项目必须保留为未完成。完整关系体系不能只用一次交谈加好感替代。

## 5. 建议的测试与后续研究

1. 固定种子跑多次应产生相同事件序列；更换种子改变具体结果但不破坏约束。
2. 30分钟自动模拟观察：不同活动数、社交邀请与拒绝数、完成/取消原因、最长空闲时间、同一事件重复率；不能把加速模拟冒充30分钟真人游玩。
3. 人为构造争抢、路径失败、暂停、取消、存档载入，确认所有锁释放且事件不重复结算。
4. 浏览器实看双人站位、轮次、气泡、动作、关系变化；仅通过纯逻辑测试不代表表现可读。
5. 持续研究应记录原版版本号、创建属性、观察时段、输入操作、完整视频时间码、次数和反例。至少比较“陌生/熟悉”“刚被拒绝/长期未见”“有空/正在活动”“相同/不同偏好”。没有这些材料，不宣称概率对齐。
6. 3DS手册、社区数据表、玩家视频可作为后续线索，但必须单列版本与证据等级，不能无缝移植到2026新作。

本报告未更改游戏源码。实现状态需以本次提交的源码、测试与运行证据另行核验，研究中列出的功能不代表已经开发完成。
