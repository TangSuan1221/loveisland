# 制作人游戏系统缺口审计与制作顺序

审计日期：2026-11-12。基准文档为项目根目录《收视率暴君_完整策划案.md》v1.0。审计者为独立子 Agent，只审查产品源码和运行验证，不负责本轮实现；本报告不是无上下文盲测。下表“起点”指本轮开发开始前的 NPC 海岛版本，新增实现的结果在末尾追加，不能把计划当成已完成。

## 总结论与边界

起点可称三维 NPC 生活原型：六位固定人物、需求驱动日常、部分双人互动、关系/记忆、设施占用、三片平地路线、展示镜头和本地存档。它不具备制作人游戏的开局、回合、交付、经营压力与终局。用户指出的问题成立。

策划本身区分 P1（4人/3日切片）、P2（6人/7日/多季）及 P3（新地图/竞争收购）。“所有策划系统完成”不能用 P1 通关替代，也不能用一个简化并购按钮替代 P3 的估值、有限市场、整合任务与盈利季要求。原型初值允许调参，但应明确修改点，不能省略系统却声称严格还原。

当前剩余工作请以 [REMAINING_SYSTEMS.md](REMAINING_SYSTEMS.md) 为准：39项逐项区分当前已有、真实缺口与验收条件，并按依赖排序。下表末列是开工时验收要求，历史轮次段落按日期保留，不可当成最新缺失清单。

节奏安排应让每一段承担明确职责：开局判断阵容；晨间规划资源与机位；录制观察并消耗有限指令；午间给一次纠错窗口；剪辑比较表达；播出兑现收益与代价；季末决定如何成长。不能以持续出现的模态报表替代这些不同操作。

## 可量化验收与审查轮次

1. **流程闸门**：至少5个种子完整跑3日和7日，所有合法阶段有可用下一步；零素材、低人数、停播和破产不是无限等待。
2. **账本闸门**：每条流水前后余额一致，总现金等于初始现金加全部流水；重复锁片/日结/结案/残值/里程碑请求均不重复获利或付款。
3. **事实闸门**：同一存档做两种剪辑，事实、NPC关系与已知事实保持不变；市场与风险可以变化。剪辑预览不消耗未来NPC随机流。
4. **场景闸门**：选角、建设数据与3D数量一致；移动设施后人物服务与机位覆盖使用新位置；非法布局与无路径有反馈。
5. **例外闸门**：退出后原素材仍引用有效；抢占/取消释放预约；维护/停更推进经营日和到期事项；新季不洗掉案件债务。
6. **成长闸门**：升级现金与经验都扣/检验，重复里程碑不发经验；MCN同一季不可同时商务与参演；收购有成本与后续条件。
7. **独立首次游玩**：另一个不读源码/策划的Agent，只从游戏界面摸索并记录每次阻塞、理解错位与完成条件。逻辑脚本通过不能替代此项。
8. **视觉与沉浸闸门**：实际截图检查信息层级、可读性、构图遮挡、动画一致、场景交互反馈、分辨率适配；建立P0/P1缺陷列表并复检。没有客观统一的“3A分数”；只可报告与参照相比的不足及是否达到具体门槛，不能让同一团队的惊艳感成为认证。

本轮采用“实现→独立失败复现→修订→同用例复测”的循环。工具中不存在可执行的 `/loop` 或 `ultracode` 命令，不能虚构调用；实际迭代记录应留下版本哈希、测试操作、结果与仍未通过项。
